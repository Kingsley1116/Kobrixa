# Declarative plugin UI v1

Implementation preview for the pending API 1.6.0 publication (P160); full acceptance is not complete.

API 1.6.0 introduces data-only panels and status contributions. Plugins are trusted local programs: a utility process is crash isolation, not an OS security sandbox. UI resources cannot contain HTML, JavaScript, CSS, SVG, URLs, webviews or remote content. All controls are rendered by the host.

Use `apiVersion: "^1.6.0"`, declare `ui.panels`/`ui.status` only when needed, and place a version-1 JSON resource beside the executable bundle. Contribution IDs start with your manifest ID and a dot. Panel declarations use `location: "right"`; status v1 contains only text, tone, data and optional visibility. A static-runtime plugin cannot declare either contribution, including empty arrays.

The executable fixtures in `tests/desktop/fixtures/declarative-ui` show the complete manifest, all 14 component kinds and JS/Python consumers. `group`, `text`, `help`, `textInput`, `number`, `range`, `choice`, `boolean`, `action`, `holdAction`, `status`, `alert`, `progress` and `keyValue` are the entire v1 vocabulary. Each input field belongs to exactly one node; every non-root node has one parent, every node is reachable and cycles are invalid. English `en` text is required; `zh-TW` is optional. Text is literal, not markup. Local IDs match `^[a-z][a-z0-9-]{0,31}$`.

A resource has at most 256 nodes and depth 8, at most 256 KiB of actual UTF-8 bytes, at most 1 MiB per source and 8 MiB per host. There are at most four panel declarations and two statuses per source, 16 panels and 16 statuses per host. Serialize first when checking bytes: Unicode code points and UTF-8 bytes are different limits. Do not truncate an oversized resource; validation rejects it before activation.

A command used by a panel declares `invocation: "context-v1"` and its finite scalar argument schema. Register it with JS `commands.registerContext` or Python `@plugin.context_command`; return the raw command value `{output:{},fieldErrors:[]}`. The SDK validates it and supplies the business-result envelope; handlers must not wrap it in `ok`/`value`. Existing `commands.register`/`@plugin.command` still use `command/execute` and return null on the wire. Initialize's four fields remain unchanged. The host negotiates envelope/resource versions separately, creates bindings, then sends `ui/ready`; initialize, negotiation and ready share one 10-second deadline. Register callbacks during activation and use ready for initial UI queries. Do not wait for ready-dependent calls inside activation.

`ui.instances`, `ui.state` and `ui.patch` operate only on the caller's live bindings. A patch changes declared data slots atomically with an exact `baseRevision`. It never changes the tree, labels, commands or form draft. One panel accepts at most 10 patches per second; the renderer queue is at most four updates/64 KiB. Read a snapshot after a stale result or event gap and decide explicitly what to do next; do not replay mutations. Subscription delivery is bounded, callbacks are serial, ack follows validated bounded enqueue, and `events/unsubscribe` returns removed true then false. It is also the only unsubscribe wire method for later settings watchers.

The host creates command context, invocationId, actionRef, binding and motion references. Arguments with similarly named fields do not gain authority. invocationId deduplicates an invocation; actionRef is a separate one-use, five-second user-action reference. Export/copy arrive with persistence in 1.7.0, and must never use invocationId as authorization. A management invocation has no panel binding or motion scope. A timer, ready callback or heartbeat cannot create a user action.

Hold input is owned by the trusted renderer/main bridge. A 100 ms challenge cadence and 350 ms expiry bound liveness; plugins cannot send their own renewals. Release, cancel, lost capture, form/mode change, hide, tab/sidebar switch, collapse, blur or minimize revoke view intent. Delayed start/reply cannot revive it. A stop request and a physically confirmed stop are different states; core recovery retains uncertainty. Recordings are not a v1 UI feature: hiding a future Lab view does not stop its background work, while 3D and real persistence define its checkpoints.

`uiResourceGeneration` identifies resource lifetime, separately from process generation/processEpoch and hostEpoch. A replacement or retirement removes old bindings and gestures immediately. Process restart is lazy after explicit user action; commands and motion are not replayed. Three failures in five minutes stop activation until explicit reload or disable→enable. Required builtins cannot be disabled. Delivered optional builtins default enabled and can be independently toggled without developer mode; user choices survive restart. Optional-only unclean exit does not by itself lock safe mode. Third-party/development risk and renderer unresponsiveness do. Cold safe mode starts no optional process/provider; core management and recovery remain available.

Plugin tools uses sibling tabs, exclusive with other right-side panes. The actual motor tab moves out of the monitor card with 3C. Generic contributed settings reuse host controls: booleans/choices apply on change, valid text/numbers on blur or Enter, and reset saves one field. There is no Apply button. Invalid drafts and save errors stay visible; an external revision conflict requires reload or explicit retry. The real settings/storage service is delivered in 1.7.0; the v1 host adapter alone does not prove persistence.

Installed node features use `app.asar.unpacked/.vite/build/plugins/<slug>/main.cjs`, `kobrixa-plugin.json`, `resource-index.json` and declared JSON resources. Each entry bundles its SDK/protocol dependencies and launches using Electron utilityProcess and MessagePort. There is no PATH Node, runtime download, source-checkout or workspace-node_modules fallback. The sorted index has at most 32 files and 16 KiB, with SHA-256 and byte lengths; the entry is at most 16 MiB. Hash validation detects corruption, not authenticity. Product entries arrive with 3C motor, 3D Lab and 3E device; synthetic acceptance fixtures do not claim these products shipped.

The desktop uses one profile writer. A second launch focuses/restores the first window and starts no second workbench/provider/plugin runtime. Normal close waits for device stop/readback/journal and persistence disposition before process teardown: storage 10 seconds in parallel with stop 15 seconds plus journal 5 seconds, then manager 4 seconds; 24-second cleanup and 25-second outer safety net are not permission to force-close. Save/stop uncertainty keeps a core blocker. Healthy consumers survive release, Disconnect, suspend and provider loss; renderer/window destruction retires them. Resume does not replay motion or recording. Real Lab save/retry/checkpoint acceptance remains open until X-T1 and 3D.

Run the Node helpers, real UI smoke, synthetic installed test and production packaged smoke separately. Record artifact/platform, commands/exits, raw traces and unresolved gates. Accessibility at both themes/locales, 320 px, 125% scale, real USB/Wi-Fi safety and clean installed environments require controller acceptance. Do not convert skipped Python, mock ports or the stage-2 V01–V04 exceptions into passing integration results.
