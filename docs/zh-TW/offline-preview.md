# 本地機器人模擬器

開啟 Basic Plus 專案，選擇 **本地模擬器**，或按 **Alt+F5**。模擬器會顯示在編輯器旁，完全在本機執行，不需要 EV3 或網路，也不會上傳或控制實體設備。

按 **展開工作區** 可暫時收起程式編輯器，讓模擬器使用整個工作區；按 **顯示程式編輯器** 可恢復並排，不會重新開始模擬。點擊原始碼位置也會自動恢復編輯器。較小視窗仍保留按鈕與文字尺寸，設定欄可捲動。

工具列的 **場地** 選單可選擇 **練習場地** 或 **WRO Double Tennis 2026**。專案中沒有 `kobrixa.simulator.json` 時，會從練習場地開始，由目前專案控制一台機器人。切換場地會改用另一個場地的預設場景；若目前場景有未儲存的修改，會先要求確認。

在 WRO Double Tennis 2026 場地上，由目前專案控制 A1，其餘三台機器人停用。切換 **比賽** 時，停用機器人會改用內建對手；已設定專案程式的機器人保留原本入口。每台機器人可指定不同的專案內 `.bp` 檔案。

## 執行與檢視

- **開始／暫停**：執行或暫停世界。若開啟中的程式或專案素材自上次編譯後有修改，或上次執行已結束，按開始會自動儲存並編譯；否則從暫停處繼續。準備失敗時顯示診斷，不會改跑舊版本。
- **單步 (10ms)**：將整個世界推進 10 毫秒，包括所有機器人、物理、感測器及程式排程。在設定狀態下也可使用，會先準備場景，必要時先編譯。這是世界時間步進，不是原始碼單行步進。
- **重置**：停止執行並回到初始場景，還原機器人與球的原始位置、程式狀態與原始素材。下次按開始會重新編譯。
- **速度**：選擇 0.25×、0.5×、1×、2× 或 4× 播放速度；物理時間步長不變。
- **儲存場景**：將設定存至專案中的 `kobrixa.simulator.json`，使用一般編輯器儲存與衝突處理流程。場景檔保存設定，不保存即時執行狀態。關閉場景 JSON 編輯分頁時，也會關閉對應的模擬畫面，避免捨棄修改後仍繼續執行舊場景。

編輯器始終保留在模擬器旁。編譯後若再修改程式，模擬器會顯示「程式已修改，按『開始』以新程式重新執行。」；在下次編譯之前，執行中的程式不會被替換。

在場地、機器人資訊卡或選單選取機器人。**即時檢視**提供 LCD、按鈕、馬達速度與角度、感測器讀值、原始碼位置、呼叫堆疊與變數；來源連結會將焦點移到編輯器。大型變數預覽有容量限制並顯示提示，程式內的完整資料不受影響。`NaN`、`Infinity`、`-Infinity` 會如實顯示。

每張機器人資訊卡會分別顯示指定的 `.bp` 檔名或內建對手等級，以及執行狀態。將游標停在程式名稱上可查看完整的專案相對路徑。控制來源以目前模擬場景為準；在編輯器開啟另一個原始碼檔案，不會改變機器人正在執行的入口。

可獨立切換軌跡、感測範圍、朝向、碰撞提示與限制區域；碰撞提示標記最近一秒內發生接觸的機器人。任何機器人的程式出錯時，頂部警示都會顯示原因與來源位置，可直接切換至該機器人並查看原始碼。

可用滑鼠或取得焦點後的空白鍵／Enter 按住 EV3 按鈕；按鈕區內也支援方向鍵及 Backspace。失焦會解除按鈕。隱藏模擬器或應用程式會暫停世界；移除工作區會終止 worker，恢復時需再按開始。編譯期間若重置、關閉、隱藏或更換場景，會取消尚未完成的準備；稍後回傳的結果不會啟動已捨棄的執行。

## 場景設定

設定隨時可以修改。在執行中或暫停時修改設定，場景會自動重置，並顯示「已重置場景以套用設定。」

可拖動機器人及球，也可輸入座標。拖曳空白處平移，以滾輪、＋／－或符合場地調整縮放。座標以場地左下角為原點、單位為毫米，+X 向右、+Y 向上；朝向以 +X 為零度、逆時針增加。機器人局部座標的 +X 向前、+Y 向左。

在 WRO 場地上，**套用種子**依目前種子重建球位與比賽時間；**新種子與球位**更換種子並產生新配置。保存場景或重置執行，可重現相同設定；亦可手動移動球。

**機器人設定**分為兩部分：

- **基本**：**機器人預設**、**控制器**（專案入口、內建對手——簡易、標準或困難——或停用）、**左馬達**與**右馬達**的埠，以及端口 1–4 各自的感測器種類。
- **進階**（預設收合）：
  - 名稱、隊伍與起始位置（X、Y 及朝向）。
  - 車身尺寸與質量。
  - 差速、三輪全向、四輪全向驅動；各輪的馬達埠、位置、滾動方向、直徑、馬達轉數／輪子轉數齒輪比、反轉及輪胎碰撞行為。
  - 感測器安裝位置、角度、範圍與視角。
  - 推球板寬度及深度。
  - 發射器的獨立馬達埠、安裝位置、仰角、馬達行程、球速及拾球範圍。四輪驅動使用 A–D，因此停用發射器。

埠衝突、不可能的輪組配置、重複機器人名稱及超出範圍的數值，會在開始前指出。在 WRO 場地上，每隊最多兩台機器人，場景最多四台。

### 機器人預設與端口警告

**機器人預設**可一次套用整組硬體設定；名稱、控制器與起始位置保持不變。

| 預設                       | 硬體                                                                                                     |
| -------------------------- | -------------------------------------------------------------------------------------------------------- |
| **Driving Base（教育版）** | LEGO Education 核心套裝的基本車：大型馬達接 B（左）與 C（右）；端口 1 觸碰、2 陀螺儀、3 顏色、4 超音波。 |
| **WRO 預設機器人**         | WRO Double Tennis 預設場景使用的機器人。                                                                 |
| **自訂**                   | 修改任何預設內容後自動出現。                                                                             |

編譯後，模擬器會比對程式中以常值寫出的馬達字母及感測器端口號碼與機器人設定。若不相符，例如驅動馬達 A，但 A 沒有接輪子或發射器；或讀取端口 4，但該端口沒有設定感測器，就會顯示警告及 **開啟機器人設定** 按鈕。警告不會阻止執行。以變數保存的端口不會檢查。

## 練習場地

練習場地與 WRO 場地使用同樣 2,362 × 1,143 毫米的桌面：白色底面加邊牆，以及一條 20 毫米寬的黑線，構成圓角矩形迴圈。黑線中心線範圍為 x 400 至 1,962 毫米、y 250 至 893 毫米，轉角半徑 200 毫米，可讓顏色感測器練習巡線。

場景只有一台機器人，由目前專案控制。它從迴圈下方直線上的 (600, 250) 出發、朝向 +X，使用 **Driving Base（教育版）** 預設。場上沒有球、分數、種子、比賽計時、對手、斜坡、中央障礙，也不套用中線或紅色區域規則。機器人任何部分超出場地時，模擬仍會暫停並記錄違規。場景檔以 `ruleset: "practice"` 記錄練習場地；WRO 場景為 `"wro-double-tennis-2026"`，加入練習場地前保存的場景檔會以 WRO 場地載入。

## 內建對手

內建對手能取得的資訊與專案程式相同：自身安裝的感測器與馬達編碼器，加上公開的場地配置及自己的機器人設定。它不會讀取其他機器人或球的真實位置。內建對手僅適用於 WRO 場地。

- 以輪子編碼器和陀螺儀推算自身位置；先依陀螺儀反轉設定還原轉角，再套用起始朝向及隊伍座標轉換。顏色感測器經過印刷線條或坡道色帶時會修正誤差。它與中線及己方紅色坡道區保持一個迴轉半徑以上的距離，不會越過對方半場。
- 尋找己方半場的橘球，暫時離開視野的球也會記住；己方半場的紫球（每顆對該方 −2）則不去碰。優先讀取已安裝的 `KOBRIXA-VISION`，否則透過程式也能使用的 I2C API 讀取 Pixy2 色塊，依相機幾何、外框大小和球徑估算方位與距離。發射器範圍內有紫球時不會發射。
- 會繞到球後方對準，把球射向對方半場；沒有發射器時改用推球板推送。看不到球時會在己方半場巡邏、掃描，而不是原地打轉。
- 同隊兩台啟用的機器人會把半場分成上、下兩區，網子後方區域共用；隊上只有一台時則負責整個半場。
- 由超音波或視覺判斷被其他機器人或卡住的球擋住時，會後退、轉向並改選目標。

| 等級 | 行為                                                                   |
| ---- | ---------------------------------------------------------------------- |
| 簡易 | 半速、反應較慢、瞄準較鬆，只追目前看得到的球，只會直射。               |
| 標準 | 預設等級。速度較快，會記住球數秒，可斜角射球。                         |
| 困難 | 反應最快、可更靠近中線、射角更廣，並會利用己方後牆反彈，救出貼牆的球。 |

在加入等級之前保存的場景會以標準等級載入。兩種視覺感測器皆未安裝時，機器人會在負責區域來回掃推，而不瞄準特定的球。Pixy2 無法辨識未訓練的顏色，也無法區分設定相同色碼的橘球與紫球；內建對手不會猜測其球種。影像邊界截斷的色塊不能用作精準射球定位。這些估算不會讓內建對手取得球的真實位置。

## 感測器與本機通訊

感測器讀值由世界模型產生。請讓感測器位置與程式設定相符。

| 感測器 | 模型與讀值                                                                                                                                                                 |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 顏色   | 讀取安裝位置下方的場地。模式 2 為顏色編號、模式 4 為 RGB、模式 3 為原始反射通道，其餘為光線百分比。光照與校正是近似模型。                                                  |
| 超音波 | 向場景發出扇形射線。模式 1／4／6 回傳英吋；一般距離模式回傳公分；模式 2 聆聽回傳零。                                                                                       |
| 陀螺儀 | 量測相對於初始朝向的角度及角速度。模式 3 同時回傳角度與速度、模式 1／2 回傳速度，其餘回傳角度。                                                                            |
| 觸碰   | 使用設定方向的近距離接觸近似模型。                                                                                                                                         |
| Pixy2  | 依可見球體產生 LEGO I2C 色塊。可設定訓練色碼、相機高度、俯仰和水平／垂直視野；使用既有 I2C API 讀取數量與外框。                                                            |
| 視覺   | 合成 `KOBRIXA-VISION` 感測器，類型 124。SI 通道為 `[偵測到、方位角度、距離毫米、類別]`，類別 1 為橘球、2 為紫球；模式 0／1／2 選擇全部／橘球／紫球。未偵測到時回傳四個零。 |

視覺是模擬器功能，不是特定攝影機模擬。它檢查範圍、視角及場景遮擋，選出最近的可見球。

### Pixy2 LEGO 相機

在機器人設定將感測器種類選為 **Pixy2 相機（LEGO）**。預設水平視角 60°、垂直視角 40°、範圍 2,500 mm、安裝高度 100 mm、俯仰 −10°。安裝高度由車身底部起算，車身底部隨斜台升高；俯仰正值朝上。橘球預設色碼 1、紫球色碼 2；每種球色可選色碼 1–7，或「**未訓練**」（0）。兩種球色設定相同色碼時會合併辨識。這些設定會隨場景儲存。

相機把可見球體投影成影像色塊，考慮安裝位置、朝向、高度、球體高度、範圍、視角和遮蔽。LEGO 封包使用 0–255 的無號位元組座標，X 向右、Y 向下，按照製造商韌體縮放，而非 Pixy2 原始影像像素。距離可由色塊大小估算，不提供距離欄位。此功能模擬色塊辨識，不包含影像處理、巡線、RGB 讀取、影片、追蹤 ID 或多色組合色碼。

使用既有 Basic Plus I2C API，裝置位址為 **1**：

| 讀取方式                                                        | 回傳位元組                                                                     |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `Sensor.ReadI2CRegisters(port, 1, 80 + signature, 5)`，色碼 1–7 | `[數量, x, y, 寬, 高]`，回傳該色碼最大色塊；數量包含所有可見且符合色碼的球體。 |
| `Sensor.ReadI2CRegisters(port, 1, 80, 6)`                       | `[色碼低位元組, 色碼高位元組, x, y, 寬, 高]`，回傳所有色碼中的最大色塊。       |
| 暫存器 `0x42`、長度 1                                           | 最大色塊的 X。                                                                 |
| 暫存器 `0`、長度 5                                              | 版本字串 `V0.4`，包含結尾 NUL 位元組。                                         |
| 暫存器 `8` 或 `16`、長度 6                                      | 廠商／裝置識別字串 `Pixy2`，包含結尾 NUL 位元組。                              |
| 暫存器 `0x60`、長度 1                                           | 零；場景只模擬單一顏色色碼，沒有組合色碼角度。                                 |

沒有可見目標時，支援的色塊讀取仍回傳要求的位元組數，每個位元組皆為零。可縮短讀取長度以取得回覆前綴；超過表列回覆長度時會拒絕讀取。`Sensor.GetName(port)` 為 `Pixy2`；模式 0 的 SI／raw 僅提供最大色塊的 X，並非 `KOBRIXA-VISION` 的四個通道。`Sensor.GetType` 使用模擬器通用 I2C 值 100，不是廠商硬體識別碼。支援暫存器 `0x62` 的燈光指令，但不改變場景照明。其他協定及未支援的暫存器會指出原因，不會假裝完成硬體通訊。

[Pixy2 範例](../../examples/simulation/pixy2-search/)會讀取並顯示色碼 1，不移動機器人。封包格式參考[製造商 LEGO I2C 韌體](https://github.com/charmedlabs/pixy2/blob/master/src/device/main_m4/src/serial.cpp)；[LEGO 積木說明](https://docs.pixycam.com/wiki/doku.php?id=wiki:v2:pixy_lego_block)介紹色碼選取及色塊量測。實體 Pixy2 需另外設定介面和訓練顏色；模擬器不會連接實體相機。

本機 Mailbox 可在同隊機器人之間傳送資料。目標必須是完整的機器人 ID 或名稱；不支援廣播與外部連線。文字及數字信箱型別必須相符。寫入於下一個世界步驟生效；信箱只保留最新未讀資料，接收後消耗，沒有資料時等待。多個同時寫入依固定發送者順序處理，不使用 Bluetooth 或電腦網路。

## 比賽與物理範圍

比賽規則、球與斜坡只適用於 WRO Double Tennis 2026 場地；練習場地使用相同的機器人物理與感測器模型，但不包含這些內容。

WRO 場地為 2,362 × 1,143 毫米，包含標線、邊牆、中央障礙、斜坡、兩側十顆球及中央橘球。輪組幾何將馬達運動轉換為差速或全向移動；車身與球會碰撞，推球板可移球，發射器在 2D 剛體模型之外加上簡化垂直拋射軌跡。

每座斜台是底面 300 × 563 毫米的實體楔形，沿 300 毫米方向由 0 升至 50 毫米。球場以箭頭標示上坡方向、數字標示高度，粗線表示最高端的垂直面。機器人和球可從低端上坡；側邊及高端的垂直面會阻擋低於該處台面的物體。飛行中的球必須有足夠高度才能越過斜台，距離及視覺感測也會受到斜台遮擋。車身底部使用簡化高度模型，不模擬車身俯仰、懸吊或上坡馬達負載。畫面維持俯視圖，高度陰影不會改變實際碰撞範圍。

輪胎碰撞行為預設為「碰撞時空轉」（`wheelTraction: "slip"`）。靠編碼器停轉判斷撞牆的程式，應選「碰撞時輪子停轉（近似）」（`"grip"`）；輪子行程會跟隨碰撞後實際可移動的距離，倒車即可脫離。這是抓地近似，並非馬達扭矩模型。重設編碼器仍不會改變車身位置。

種子決定的擲骰比賽時間為 70–120 秒，也可手動修改。比賽模式到時停止；練習模式繼續並將分數標示為暫定。各側橘球 +1、紫球 −2，分數較低者勝。未移動的中央球不計分。接觸球歸屬會反映在暫定分數中。機器人進入紅色坡道區、車身越過對方半場或機器人外形任何部分超出場地時，模擬會暫停並記錄違規。球離開場地時會放回指定角落：橘球回到責任隊伍、紫球回到另一隊，並暫停世界。違規後按開始會以練習方式繼續並使用暫定分數，原本為比賽模式時亦同；不自動套用官方裁判罰則或人工判定。

摩擦、抓地力、碰撞、馬達反應、斜坡、重力、感測器及視覺皆為近似。模型不重現輪胎變形、精確馬達負載、車身俯仰與懸吊、攝影機影像處理或所有競賽判例。適合程式開發與可重複實驗，仍需另外驗證實際機器人、安全性與官方判分。

## 程式支援與限制

程式以編譯後的 KobrixaIR 執行，支援 float32／int32 數值、分支、迴圈、函式、陣列、合作式執行緒及已支援的 EV3 函式庫。LCD 圖形及 RGF 素材在本機顯示；音調與未壓縮 RSF 以時間及輸出事件呈現，不播放音訊。專案素材為編譯時快照；可寫的虛擬檔案僅存在記憶體，重設後清除。

每個程式素材最多 64 個檔案、總量 1 MiB。指令、執行緒、呼叫深度、文字及陣列都有容量限制。物理與解譯器在獨立 worker 中分批執行，無限迴圈不會佔住編輯器。事件與軌跡保留有限歷史。

這不是原生 `.rbf` 韌體模擬器。不支援電腦系統指令、實體 I2C／UART／第三方通訊、Daisy-chain 設備或外部網路。素材缺漏、不支援的操作及執行錯誤會顯示原因與可用的程式位置，不回傳虛構成功結果。

## 範例與規則來源

[模擬器範例](../../examples/simulation/README.md)提供差速路線、全向橫移、視覺尋球、Pixy2 I2C 色塊、馬達射球及雙機 Mailbox 協作。從 IDE 範例庫開啟任一專案，再按 Alt+F5，即可載入隨附場景。

場地與配置參考 [WRO 2026 Double Tennis 官方規則](https://wro-association.org/wp-content/uploads/WRO-2026-RoboSports-Double-Tennis-General-Rules.pdf)及[官方 Q&A](https://wro-association.org/competition/questions-answers/)。物理引擎 [Planck.js](https://github.com/piqnt/planck.js)隨桌面應用程式打包，執行時不需要下載任何球場素材或程式庫。

世界固定每 10ms 執行一步，每台機器人每步最多 1,000 條 IR 指令；播放速度只控制每次處理的步數。相同程式快照、場景、種子與操作在同一執行環境可重現；不承諾跨平台浮點運算逐位相同。
