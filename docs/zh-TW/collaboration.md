# 雲端協作

> **候選版本。** 雲端協作已在候選分支實作，尚未納入已發布的桌面版本。預設服務 `https://collab.kobrixa.com` 已部署，可供此候選版本使用。

透過 Kobrixa 營運的協作服務，多人可以同時編輯同一個 Kobrixa 專案。不需要帳號：主持人開啟房間並分享邀請碼，其他人輸入邀請碼，以及主持人選擇設定的房間密碼，即可加入。所有人看到相同的檔案、游標與聊天內容；同一時間只有一人能控制 EV3。

## 開啟與加入房間

**主持人：**開啟專案後，切換到工具面板的「協作」分頁，輸入顯示名稱，再按「開啟房間」。可在對話框設定房間密碼，也可以留白。分頁會顯示 `ABCD-EFGH-JK23` 格式的邀請碼，把它分享給要邀請的人。

**來賓：**開啟「協作」分頁，輸入邀請碼與顯示名稱；若主持人有設定房間密碼，也需輸入密碼後加入。來賓不需要事先取得專案，專案內容會從房間同步過來。

- 顯示名稱最多 40 個字元；每個房間最多 16 人。
- 未設定密碼時，持有邀請碼即可加入；設定密碼後則兩者都需要。請只分享給要邀請的人。
- 房間密碼區分大小寫、保留空白，最多 128 個字元。服務端只儲存加鹽的密碼驗證值，不儲存密碼原文。
- 應用程式只在記憶體保留房間存取權杖，協作不使用系統鑰匙圈，也不儲存密碼。結束應用程式或離開房間後會忘記存取權，需要用邀請碼與房間密碼（如有）重新加入。原主持人重新加入會成為來賓；若要再次主持，請建立新房間。
- 房間存取權杖由服務簽署，在該次工作階段內有效期限為 7 天。

## 角色

| 角色   | 可執行的操作                                                     |
| ------ | ---------------------------------------------------------------- |
| 主持人 | 編輯者可做的一切，另可變更參與者角色及移除參與者                 |
| 編輯者 | 編輯檔案、建立／重新命名／刪除檔案、在聊天中發言；來賓的預設角色 |
| 檢視者 | 唯讀：可觀看編輯過程與閱讀聊天，但不能編輯、發言或變更檔案       |

被移除的參與者會立即斷線，其權杖也會失效。

角色變更時，該參與者會重新連線並載入房間已確認的文件狀態。檢視者期間被拒絕的編輯會被捨棄，不會在升為編輯者後重新送出。

## 共同編輯

`.bp`、`.bpi`、`.bpm` 與 `.json` 專案檔可即時共同編輯。編輯器會顯示每位參與者的游標與選取範圍，並標示名稱與代表色。檔案樹同樣共享：建立、重新命名或刪除檔案都會同步給所有人。

共享專案最多 200 個檔案，每個檔案最多 1 MiB，全部共享文字合計最多 8 MiB（以 UTF-8 計算）。資料夾不計入檔案數量。開啟房間時，超出限制的檔案會被略過，並列在同步狀態中。

同時發生的共享文字編輯會由 Yjs 自動合併。本機磁碟寫入仍會檢查檔案版本；需要處理的寫入錯誤或外部變更衝突會由應用程式提示。

## 檔案存放位置

- **主持人：**編輯內容寫入主持人自己的專案資料夾，與一般使用相同。
- **來賓：**專案會鏡像到應用程式使用者資料目錄中的 `<userData>/collab/<room>/`。來賓可以在這個鏡像中建置、使用模擬器，並在持有設備控制權時上傳到自己的 EV3。

## 設備控制權

為避免多人同時操作同一台 EV3，只有持有設備控制權的參與者能上傳、執行或部署程式、開始馬達測試、管理 EV3 檔案及切換感測器模式。控制權預設屬於主持人；其他參與者可以提出請求，由主持人授予或收回。

無論控制權在誰手上，任何人都可以停止正在執行的程式。

## 聊天

「協作」分頁內建純文字聊天。每則訊息最多 2,000 個字元，房間保留最近 500 則訊息。檢視者可以閱讀但不能發言。

## 隱私與資料

- 房間使用期間，專案檔案、聊天訊息與顯示名稱等內容會儲存在協作服務上；連續 7 天沒有任何連線後自動刪除。
- 服務在 Cloudflare 上執行，因此原始碼會經過 Cloudflare 的網路。
- 請勿公開張貼邀請碼或房間密碼；能加入房間的人都能讀取專案，以編輯者身分加入時也能修改專案。
- 應用程式只連線到設定的協作服務來源；Content-Security-Policy 只允許該來源，不允許其他協作端點。

不得交由第三方服務處理的內容，請不要透過協作功能分享。

## 開發者說明

預設服務為 `https://collab.kobrixa.com`。啟動桌面應用程式前設定環境變數 `KOBRIXA_COLLAB_URL` 即可改用其他服務，例如本機服務：

```sh
cp apps/collab/.dev.vars.example apps/collab/.dev.vars   # 接著設定 COLLAB_SECRET
pnpm --filter @kobrixa/collab dev
KOBRIXA_COLLAB_URL=http://localhost:8787 pnpm dev
```

`COLLAB_SECRET` 是簽署房間權杖用的 HMAC 金鑰，本機使用任意夠長的隨機字串即可；`.dev.vars` 已被 Git 忽略。若 `wrangler dev` 顯示的位址與範例不同，請改用實際位址。服務邊界詳見[架構與公共契約](../zh-TW/architecture.md#雲端協作)。

編碼後的 Yjs 文件及單一 WebSocket 訊息上限為 16 MiB，以限制同步與歷史資料的額外用量；超大的更新會在接受前被拒絕。這些服務限制讓房間快照維持在平台的訊息與記憶體限制內。

執行 `pnpm build:core && pnpm test:collab:live` 可使用兩個客戶端測試真實本機 Worker，涵蓋無密碼與有密碼房間、錯誤密碼、記憶體憑證、檔案鏡像、編輯、聊天、控制權、角色變更、移除成員及 Worker 重啟後的資料保留。執行 `KOBRIXA_SMOKE_COLLAB_LINKED=1 pnpm test:desktop:smoke` 可驗證整合後的桌面操作流程；兩者皆使用本機測試資料。

部署服務後，執行 `pnpm test:collab:remote https://collab.kobrixa.com` 可對指定服務驗證相同的雙客戶端流程。測試會建立兩個僅含測試檔案與聊天內容的房間，結束後關閉所有客戶端；房間會依一般的閒置七天政策自動刪除。此模式會以全新客戶端確認伺服器狀態及被撤銷的存取權仍然有效，不會重啟已部署的 Worker。必須明確指定服務來源；HTTP 僅允許用於迴路位址。

## 驗收狀態

候選版本包含自動化單元、本機 Worker 與 Electron 整合測試。預設公開服務已於 2026-10-08 更新，並通過包含選填房間密碼的雙客戶端線上流程驗證。桌面版本仍須完成發布驗收，才能納入已發布的應用程式。
