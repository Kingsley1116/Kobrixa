Parity here means coverage of the programming lessons, API families, and hardware workflows in that tree. ## Coverage and learning order / 覆蓋與學習順序

[All 122 reference APIs](CLEV3R-API-COVERAGE.md) have an example in the new curriculum. `pnpm examples:coverage` compiles only the 61 new projects, checks the exact 41-program mapping and eight helper/asset mappings, and rejects a missing reference API.／[參考範例使用的 122 個 API](CLEV3R-API-COVERAGE.md) 均有新範例。覆蓋檢查僅編譯 61 個新專案，核對完整 41 主程式、8 輔助檔／素材及 API，任何缺漏都會失敗。

1. Greeting, loop exits, typed functions, bytes, includes and nested modules.／問候、迴圈跳出、型別函式、位元組、引用與巢狀模組。
2. Row/Vector lifecycle, mixed binary files, timers, recursive Hanoi and computation/drawing benchmarks.／Row／Vector、混合二進位檔案、計時、遞迴河內塔及運算繪圖基準。
3. Buttons, animation, note sequencing and media deployment in internal/SD folders.／按鍵、動畫、音符，以及內建／SD 媒體部署。
4. Encoders, steering, synchronization, paired motor trajectories, sensor modes/raw channels, HiTechnic compass/IR and multi-byte I²C.／編碼器、轉向同步、雙馬達軌跡、感測模式／原始通道、HiTechnic 羅盤／紅外線及多位元組 I²C。
5. Scheduled actions, battery under load, concurrent workers with mutexes, daisy-chain addressing, and paired mailbox sender/receiver.／排程動作、負載電池資料、互斥並行工作、串接定址、配對信箱發送／接收。

Read each project's bilingual README for wiring, inputs and expected results. Use the mailbox receiver first and match the sender's brick name; the SD lesson requires an SD card.／每個專案的雙語 README 都列有接線、輸入與預期結果；信箱先啟動接收端並配對主機名稱，SD 範例需 SD 卡。

## Build and bytecode verification / 建置與字節碼驗證

From the repository root, install dependencies, then download the pinned EV3 opcode tables once.／在根目錄安裝依賴後，下載固定版本的 EV3 指令表。

```sh
curl -fLsS https://raw.githubusercontent.com/mindboards/ev3sources/78ebaf5b6f8fe31cc17aa5dce0f8e4916a4fc072/lms2012/lms2012/source/bytecodes.h -o /tmp/kobrixa-new-bytecodes.h
curl -fLsS https://raw.githubusercontent.com/mindboards/ev3sources/78ebaf5b6f8fe31cc17aa5dce0f8e4916a4fc072/lms2012/lms2012/source/bytecodes.c -o /tmp/kobrixa-new-bytecodes.c
pnpm examples:parity:audit /tmp/kobrixa-new-bytecodes.h /tmp/kobrixa-new-bytecodes.c /tmp/kobrixa-parity-audit
pnpm examples:audit /tmp/kobrixa-new-bytecodes.h /tmp/kobrixa-new-bytecodes.c /tmp/kobrixa-first-batch-recheck
pnpm examples:coverage
pnpm test:examples:audit
```

Use suitable temporary paths and `curl.exe` on Windows. Each audit rebuilds the compiler, emits RBF images, decodes them independently against firmware tables, checks instruction/jump/CALL boundaries and memory accesses, and executes the emitted instructions against the explicit expectations in [clev3r-parity.json](clev3r-parity.json) or [new-examples.json](new-examples.json). Output includes RBF/IR/disassembly, traces, source/RBF hashes and `checked-results.json`.／Windows 請替換暫存路徑並使用 `curl.exe`。每次稽核會重建編譯器、輸出 RBF、按韌體表獨立解碼、檢查指令／跳躍／CALL 邊界及記憶體存取，再執行位元組並核對清單中的明確預期。輸出包含 RBF、IR、解碼、軌跡、雜湊與結果 JSON。

## Runtime bounds / 執行範圍

Recursive call groups use at most 32 simultaneous frames; overflow shows `Recursion exceeds 32 frames` and stops. Entry-file `Folder "prjs" "name"` or `Folder "sd" "name"` sets the media/file base and upload/run destination; use one directory name up to 48 UTF-8 bytes.／遞迴呼叫群組最多同時 32 層，超限會顯示訊息並停止。入口檔的 Folder 設定媒體／檔案基準與上傳執行目的地；目錄名稱為單一名稱，最多 48 個 UTF-8 位元組。
