# Desktop interaction smoke test

Run `pnpm test:desktop:smoke` (or `node tests/desktop/run-smoke.mjs`) on macOS, Windows or Linux with a graphical session. On Linux CI, run it under Xvfb. The test opens a focused Electron window: native editing commands require actual window focus.

The runner starts a temporary local Vite server, uses an isolated user-data directory, and loads the real React application and Monaco editor. A sandboxed preload supplies in-memory project/device services; it never connects to EV3 hardware or changes a user's projects. The native keyboard handler and background language service are bundled from production sources. The language worker checks an isolated temporary copy of the in-memory source fixtures.

Coverage includes the complete Chinese command catalog, bilingual search, language switching, dark/light themes at minimum window size and 125% scale, shortcut recording and conflict round trips, two-stroke timeouts, keyboard-only dialog operation, search by shortcut, editor remapping, undo/redo, multi-cursor operations, read-only command contexts, IME input, editor options, automatic saving without formatting, undoable manual formatting, typing during pending writes, focus-change saving, JSON worker formatting, and recovery drafts after failed saves. The temporary profile and screenshots are deleted on success; failures print the artifact directory for inspection. Set `KOBRIXA_SMOKE_KEEP_ARTIFACTS=1` to retain screenshots after a successful run. Unit tests additionally cover persistence failures, invalid settings, command translation coverage, search aliases and filters, conflicting shortcuts, chord timeout and save-queue recovery.

The renderer fixtures in `apps/desktop/tests` are development-only and excluded by desktop packaging. This test does not replace platform packaging or the EV3 hardware matrix.

`components-smoke.mjs` also exercises shared UI components in the real application: form submission and Tab trapping, unsaved-tab and delete confirmations, focus restoration, closable file/settings tabs, settings labels and keyboard controls, menu navigation across disabled items, and resizing all three panels with bounds, reset, blur, cancellation and hidden-panel cleanup.

`highlighting-smoke.mjs` verifies real Monarch tokenization and semantic token rendering with a cross-file project, Dark+/Light+ colors on the existing backgrounds, dependency edits, undo, unterminated-string recovery, and JSON isolation. Screenshots are retained with the other artifacts when `KOBRIXA_SMOKE_KEEP_ARTIFACTS=1`.

`language-features-smoke.mjs` exercises the shared worker symbol index through Monaco's providers and UI: F12 opens a closed dependency, hover and signature help show parameter types, completion respects function scope, references span files, and F2 opens all affected files as dirty tabs without writing them to disk. It also checks independent undo stops and recovery drafts in each affected file. The smoke test covers the early Monaco service initialization required for workspace edits; its default bulk edit service cannot open Kobrixa tabs.

The editor uses `@kobrixa/basic-plus/intelligence` for queries over the serialized index; project parsing and binding remain in the language worker. Renaming checks identifier validity, collisions, binding ambiguity across entry contexts, source snapshots and model versions before applying any edit. It conservatively rejects project errors, errors in another program using the symbol, built-in APIs and explicitly qualified declarations. Multi-file rename follows the existing save/auto-save policy and can be undone in each file separately. This implementation has no LSP dependency.

`performance-smoke.mjs` types continuously in a 30,000-line document and moves the cursor while checking real App render counts, full-buffer reads, content resets, semantic colors through line insertions, and undo. A Vite transform injects the render counter only into the smoke run. It asserts zero App renders and full-buffer reads during the dirty typing batch, one analysis after the 500 ms debounce, input p95 below 50 ms and frame p95 below 100 ms. `editor-performance.json` records the timings for that machine; these are smoke thresholds, not universal latency guarantees.

`interaction-performance-smoke.mjs` additionally measures immediate API completion, updating an open suggestion list with fresh project symbols, keeping dismissed suggestions closed, repeated hover without full-buffer reads, comment-only IPC deltas, a 2,000-line paste into a 30,000-line buffer, analysis merge/token application and frame gaps, actual Chromium IME composition/commit, and typing during a delayed automatic save. `interaction-performance.json` records these end-to-end timings separately from the typing microbenchmark. `KOBRIXA_SMOKE_PERFORMANCE_ONLY=1` runs only the performance scenarios for focused investigation; the default run includes all existing regressions. Timing and render probes are injected only by the smoke Vite config and are absent from production.

The live editor uses `language.sync` with ordered document revisions and an accepted analysis base. Requests send changed/removed overlays; the worker returns changed index/token sections and sources. Token ranges and occurrences use numeric buffers with interned strings to avoid cloning large nested object graphs. Unchanged token arrays retain their identities after merging, avoiding re-encoding. Cancellation advances synchronized document state while discarding stale results; worker restart reseeds overlays from the main process, and missing baselines explicitly request a reset. The original `language.analyze` and diagnostics APIs still return full results for compatibility.

Hover, definitions and token application validate accepted model identity, explicit path, workspace snapshot and content version. Full source checks remain in workspace rename validation. Completion uses a separate `language.completionSync` revision stream and dedicated worker: model UTF-16 edit batches update a cached project, with a 50 ms debounce and 150 ms maximum wait. It shares compiler parsing/resolution/binding but omits lowering, tokens and references. The renderer groups candidates by context/scope and tracks scopes through Monaco decorations. Ordinary edits retain candidates; function boundaries/import changes invalidate affected contexts. Safely mapped older completion results can supply candidates during continuous typing; strict semantic features never use them. The pinned Monaco controller adapter preserves selection, refreshes empty pending lists, and honors Escape, blur and IME.

`completion-performance-smoke.mjs` disables word-based suggestions and measures real keyboard input until a rendered, visible suggestion row contains an existing or newly declared variable. It separates index/widget startup from warm completion, verifies scope tracking, selection preservation, dismissed empty lists and a 30,000-line buffer. Thresholds are warm p95 ≤100 ms, new variables ≤200 ms and large-buffer new variables ≤300 ms. `completion-performance.json` records timings. `KOBRIXA_SMOKE_COMPLETION_ONLY=1` runs just these cases. Visibility uses rendered row geometry/styles: Monaco's `visible` CSS flag is delayed by 100 ms after showing the widget.

Document buffers and cursor subscriptions are separate from React workbench state. Monaco retains its tracked semantic ranges while analysis is pending. The persistent language worker caches unchanged disk sources and parsed files, and rebinds affected Include/Import contexts; changes can affect implicit globals throughout a context, so binding is not incremental within that context. Unit tests compare cached results with fresh analysis across changes, missing/cyclic imports, renames, deletions, error recovery, cancellation and entry switches.

## Automatic update acceptance

`KOBRIXA_SMOKE_UPDATES_ONLY=1 pnpm test:desktop:smoke` runs the real renderer update settings, bilingual progress, preview preference, Later, cancellation, failed saves, busy rejection and explicit installation handshake with a test-only IPC backend. `KOBRIXA_SMOKE_KEEP_ARTIFACTS=1` retains the screenshot and isolated profile. The production app has no configurable update host or test feed.

Release checks verify final hashes, metadata, packaged runtime modules and platform assets. Native A→B installation still requires two updater-enabled releases and the target OS: use a disposable user profile, install A from NSIS/AppImage or a signed Mac App, opt into preview if necessary, download B, exit/reopen A to confirm it did not install, then explicitly restart to update. Confirm B's version, retained settings and saved project, and repeat with offline access, a failed save and an in-progress transfer. macOS needs the approved Developer ID identity on both versions; an unsigned Mac test cannot establish native update acceptance. Use the next intended releases rather than publishing test releases. Do not claim the three-platform upgrade matrix is passed until these checks have run on each platform.

`pnpm test:desktop:packaged` starts the actual packaged application twice with an isolated `--user-data-dir`. It checks that the production main/preload/renderer and updater dependencies load, the update IPC returns the packaged version, normal quit works, and update preferences/localStorage persist after relaunch. Background networking is disabled in that temporary profile. CI runs this on all three packaging runners (under Xvfb on Linux); it does not perform A→B installation.
