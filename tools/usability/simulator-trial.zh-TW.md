# 本地模擬器學生試用腳本

> 適用版本：`feature/simulator-ux` 分支的開發版（模擬器只在開發模式啟用）。
> 設計依據：`docs/superpowers/specs/2026-10-11-simulator-ux-design.md`。
> 每位學生約需 45 分鐘：開場 5 分鐘、任務最多 30 分鐘、問卷與訪談 10 分鐘。

## 1. 目的與給主持人的說明

### 1.1 目的

這份腳本用來找出第一次使用模擬器的中學生（WRO 參賽者或 EV3 初學者）會在哪裡卡住。我們測試的是**模擬器**，不是學生。重點觀察：

- 學生能否在第一分鐘內打開模擬器並讓機器人動起來。
- 學生是否理解「改了程式 → 按一下就會用新程式重跑」的流程，不必另外重新編譯或停止。
- 機器人設定（預設、端口、感測器）是否看得懂、改得動。
- 端口警告與「程式已修改」等提示訊息是否真的有幫助。

同一份腳本給 1–2 位學生使用，最後在第 6 節的彙整表比較結果，決定下一步。

### 1.2 主持人守則

1. **請學生邊做邊說（放聲思考）。** 學生安靜超過 20 秒時，只可以問：「你現在在想什麼？」或「你在找什麼？」
2. **不要主動幫忙。** 學生在同一個地方卡住**超過 2 分鐘**才可以給提示，而且由小到大：
   - 第 1 級：「你覺得下一步要做什麼？」
   - 第 2 級：「看看畫面的某個區域（例如上方工具列／右邊的設定）。」
   - 第 3 級：直接指出按鈕或操作。
3. **每一次提示都要記錄**：時間、級別、說了什麼。第 3 級提示視為該任務「需協助完成」。
4. 不要解釋按鈕的意思，也不要說「這個很簡單」「大部分人都會」。學生問「這個是做什麼的？」時，反問「你覺得呢？」。
5. 學生說「我做錯了」時，回應「沒關係，我們是在測試軟體，不是測試你」。
6. 每個任務有時間上限；到時間就說「好，我們先到這裡」，並把狀態復原到下一個任務的起點（見各任務的「重設方法」）。
7. 不要在任務進行中修正學生的程式碼錯字；只有在錯字跟模擬器無關、且已卡住超過 2 分鐘時才可以指出。

> 給主持人的背景知識（**不要唸給學生聽**）：
>
> - 打開模擬器：選單中的「本地模擬器」或 **Alt+F5**。
> - 預設是「練習場地」：白色場地上有一圈黑線，一台 Driving Base 機器人停在黑線左下方的直線上，面向右方。
> - 機器人：馬達 B 左輪、C 右輪；端口 1 觸碰、2 陀螺儀、3 顏色、4 超音波感測器。
> - 工具列：「開始／暫停」、「單步 (10ms)」、「重置」，以及「場地」選單（練習場地／WRO Double Tennis 2026）。
> - 按「開始」會自動儲存並編譯有變更的程式；編譯後再改程式，工具列會顯示「程式已修改，按「開始」以新程式重新執行。」
> - 機器人設定分「基本」（機器人預設、控制器、馬達端口、各端口感測器）與預設收起的「進階」；設定隨時可改，修改時場景會自動重置並顯示「已重置場景以套用設定。」
> - 程式用到機器人沒有的端口時，會出現「程式用到這台機器人沒有的端口」警告，並附「開啟機器人設定」按鈕。警告不會阻止執行。
> - 注意：端口警告只在程式用到的端口**完全沒有**接裝置時出現。Driving Base 四個感測器端口都已接上，所以「把端口 2（陀螺儀）當顏色感測器讀」**不會**出現警告，只會讀到奇怪的數值。因此 T3 的故意錯誤版本用的是錯誤的**馬達**端口（`"AD"`），這也是學生從其他範例複製程式時最常見的錯誤。

## 2. 開場說明（唸給學生聽的稿）

> 「謝謝你今天來幫忙。我們在做一個電腦上的 EV3 機器人模擬器，想知道它好不好用。
>
> 今天要測試的是這個軟體，不是測試你。如果你覺得哪裡很難、看不懂，那就是軟體需要改進的地方，這正是我們想知道的。沒有對或錯的答案。
>
> 待會我會給你幾個小任務。做的時候，請你把心裡想的說出來，例如『我在找哪裡可以……』、『我以為按這個會……』。
>
> 我大部分時間不會回答問題，因為我想看看你自己第一次用會怎樣。如果真的卡住很久，我會給你一點提示。你隨時可以說想停下來或休息。
>
> （如有錄影）我們會錄下螢幕和聲音，只用來改進軟體，不會公開。你同意嗎？
>
> 有沒有問題？好，我們開始。」

## 3. 任務

每個任務先把「給學生的任務卡」唸出或交給學生，然後開始計時。**任務卡上不出現任何按鈕名稱。**

### T1：讓機器人往前走一段再停

| 項目     | 內容                                                         |
| -------- | ------------------------------------------------------------ |
| 起點     | 已開啟空白新專案，`src/main.bp` 開在編輯器中，模擬器尚未打開 |
| 成功標準 | 模擬器已打開，機器人在練習場地上向前移動一段距離後停下       |
| 時間上限 | 7 分鐘                                                       |
| 重設方法 | 不需要；T2 直接沿用                                          |

**給學生的任務卡：**

> 「你已經有一個新的專案。請在電腦上模擬一台機器人：讓它往前走一段距離，然後停下來。」

依學生程度二選一（在紀錄表註明用了哪一種）：

- **版本 A（給程式碼）**：把下面的程式碼交給學生，說「你可以用這段程式」。
- **版本 B（自己寫）**：只說「機器人的左輪接在 B，右輪接在 C」，讓學生自己寫。

```basic
' 往前走大約 35 公分，然後停下
Motor.Move("BC", 50, 720, True)
Motor.Stop("BC", True)
```

**觀察重點：**

- 學生怎樣找到模擬器（選單、快捷鍵、還是到處找）？用了多久？
- 打開後是否一眼看出機器人在哪裡、場地是什麼？
- 是否知道要按哪裡讓程式跑起來？會不會先找「編譯」「上傳」或「儲存」？
- 機器人停下後，學生是否知道程式已經跑完（狀態「已結束」是否被注意到）？
- 版本 B：學生寫錯語法時，錯誤訊息是否看得懂、能否跳到出錯的位置。

### T2：走一個正方形，然後改速度或距離再跑一次

| 項目     | 內容                                                                               |
| -------- | ---------------------------------------------------------------------------------- |
| 起點     | T1 完成後的狀態（模擬器仍打開）                                                    |
| 成功標準 | ① 機器人走出大致的正方形；② 學生修改速度或距離後，機器人用**新的**程式重新跑了一次 |
| 時間上限 | 10 分鐘                                                                            |
| 重設方法 | 把 `src/main.bp` 換成下面的正方形程式，模擬器保持打開                              |

**給學生的任務卡：**

> 「現在請讓機器人走一個正方形，回到差不多起點的位置。」
>
> （機器人走出正方形後）「很好。現在把它改快一點，或者讓正方形大一點，再試一次。」

學生自己寫不出來超過 3 分鐘時，可以給下面的程式碼（記錄為一次提示）。轉 90 度約需讓輪子反向轉 193 度。

```basic
' 走一個正方形：每邊約 35 公分，每次左轉約 90 度
For side = 1 To 4
  Motor.Move("BC", 50, 720, True)
  Motor.MoveSync("BC", -40, 40, 193, True)
EndFor
Motor.Stop("BC", True)
```

**觀察重點：**

- 修改程式後，學生是否注意到工具列出現「程式已修改」的提示？是否讀出來？
- 學生是否知道「按一下開始就會用新程式重跑」？還是會先找「重新編譯」「停止」或「重置」，甚至關掉模擬器再打開？
- 學生是否誤以為機器人在用舊程式（例如改了速度但沒有重跑就說「沒有變」）？
- 學生是否會用「暫停」或「單步」來看機器人每一步？（只記錄，不要引導）
- 學生按「重置」後，是否明白機器人回到起點、程式還沒有開始跑？

### T3：沿著黑線走（巡線）

| 項目     | 內容                                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------------------- |
| 起點     | 模擬器打開，機器人在練習場地起點；`src/main.bp` 換成下面的「故意錯誤版本」                                    |
| 成功標準 | ① 學生看到端口警告後，**自己**把馬達端口改正（改程式為 `"BC"`，或改機器人設定）；② 機器人沿著黑線前進至少半圈 |
| 時間上限 | 10 分鐘                                                                                                       |
| 重設方法 | 換回正確的巡線程式，按重置                                                                                    |

**給學生的任務卡：**

> 「這是同學寫的巡線程式，用顏色感測器讓機器人沿著黑線走。顏色感測器接在端口 3。請你讓機器人在模擬器裡沿著黑線走。」

**故意錯誤版本**（交給學生的版本；馬達寫成 `"AD"`，但這台機器人的輪子接在 B 和 C）：

```basic
' 巡線：顏色感測器在端口 3，讀反射光（0 = 黑，100 = 白）
Sensor.SetMode(3, 0)
While True
  light = Sensor.ReadPercent(3)
  turn = light - 50
  Motor.StartSteer("AD", 30, turn)
  Program.Delay(10)
EndWhile
```

**正確版本**（只把 `"AD"` 改成 `"BC"`；主持人參考用，不要給學生）：

```basic
Sensor.SetMode(3, 0)
While True
  light = Sensor.ReadPercent(3)
  turn = light - 50
  Motor.StartSteer("BC", 30, turn)
  Program.Delay(10)
EndWhile
```

> 這段程式沿著黑線的內側邊緣走（機器人在黑色上會向左修正，在白色上會向右修正）。主持人事前必須在練習場地上測試；如果在彎位衝出黑線，可把速度 `30` 降到 `20`。
>
> 學生也可能選擇把機器人設定的馬達端口改成 A 和 D，同樣算成功，但要記錄學生選了哪一種方法，以及是否明白兩者的分別。

**選用延伸（時間充裕才做）**：把程式中所有 `3` 改成 `2`（讀端口 2，實際上是陀螺儀）。這時**不會**出現端口警告，機器人會亂走。觀察學生能否從「即時檢視」的感測器數值或機器人設定找出原因。這一項用來判斷是否需要「感測器種類不符」的警告，不計入成功標準。

**觀察重點：**

- 機器人不動時，學生第一個反應是什麼（看程式、看模擬器、重按開始）？
- 學生有沒有看到端口警告？從看到到讀懂花了多久？
- 警告文字「程式用到這台機器人沒有的端口」以及「程式用到馬達 A，但 A 沒有接輪子或發射器。」是否看得懂？
- 學生是否使用「開啟機器人設定」按鈕？打開設定後，是否看得懂「機器人預設」「左馬達／右馬達」「端口 1–4」？
- 學生有沒有打開「進階」？打開後是否被大量欄位嚇到？
- 學生修改設定時場景自動重置，是否注意到「已重置場景以套用設定。」？是否感到意外？

### T4：切換到 WRO 場地，再切回練習場地

| 項目     | 內容                                                                             |
| -------- | -------------------------------------------------------------------------------- |
| 起點     | T3 結束後的狀態（最好學生在 T3 中修改過機器人設定，使場景有未儲存的修改）        |
| 成功標準 | 學生切到 WRO Double Tennis 2026 場地，再切回練習場地，並能說出切換時發生了什麼事 |
| 時間上限 | 5 分鐘                                                                           |
| 重設方法 | 任務結束                                                                         |

**給學生的任務卡：**

> 「這個模擬器也有 WRO 比賽的場地。請你換到比賽場地看看，然後再換回原本的場地。」
>
> （完成後問）「剛才切換的時候，發生了什麼事？你的機器人設定還在嗎？」

**觀察重點：**

- 學生能否找到「場地」選單？
- 出現「要切換場地嗎？」對話框時，學生是否讀了內容？是否明白「目前的場景有未儲存的修改。切換後會改用另一個場地的預設場景。」的意思？
- 學生選「切換場地」還是「取消」？理由是什麼？
- 切回練習場地後，學生是否預期之前改過的機器人設定還在？發現不在時的反應？
- 學生是否想先儲存場景？知道在哪裡儲存嗎？
